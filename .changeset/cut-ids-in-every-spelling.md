'cronheart': patch
---

A monitor name that holds a monitor id is now shown only by the id's last four digits, in diagnostics, configuration errors and a ping result's `monitor`, and the variable hint names `CRONHEART_<NAME>_UUID`. This holds when the id is written with a dash missing, next to other hexadecimal digits, with spaces, signs or a combining mark between its digits, or behind an invisible character; a run of decimal digits alone, such as a date or an address, is not taken for an id unless it is an id's length unbroken. `cronheart init` refuses such a name, one spelling an id with ligatures or fullwidth or mathematical digits, and one holding a character that does not print. A mistyped command, flag or flag value, an `--env-path` or `--config` path holding an id, and a variable `cronheart doctor` lists are no longer echoed whole, and `cronheart sync --print-env` names a monitor it leaves out because its variable would hold an id. Control, direction, zero-width and other invisible characters in a monitor's label are spelled out; spaces of every width and emoji, subdivision flags included, print as written. A base URL, an action, a command that cannot be started and a NestJS job name are no longer echoed whole either; any printed value that holds an id, such as a schedule or a channel label, is replaced by the id's last four digits. `ping()` no longer throws when the label for a check-in cannot be built.
