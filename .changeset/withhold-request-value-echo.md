A refusal on a route that carries a monitor's uuid (`get`, `update`, `delete`, `pause`, `resume`, `snooze`, `unsnooze`, `rotateUuid`, `pings`, `iteratePings`, `alerts`, `iterateAlerts` of `api.monitors`) or a signup's submitted values (`start` and `poll` of the signup client) no longer carries the service's own wording, which may repeat the uuid, the address or the device code: `error.problem` keeps no `title`, `detail` or `upgradeUrl` there, and `error.errors` keeps only the fields a request on such a route can carry (one set across the monitor routes), an item of one of them included, each with a fixed sentence in place of the service's message. A field the service names outside that set is no longer listed in a validation error's message. The same fixed sentence now stands in on the channel routes. The signup client composes each request inside the one error type a caller catches: an accessor on its options that throws rejects with `ApiInvalidRequestError` and sends nothing, where it rejected as an `unexpected` transport error before, and each option is read once. The wire contract states the withheld routes for ports as a hazard, and its agreement check between the classifier and the documented rule table now compares each row's condition, bound and patterns both ways rather than only its pointers and cells.
