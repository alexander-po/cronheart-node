A refusal from any `api.channels` call no longer carries the service's own wording, which may repeat a channel's destination: `error.problem` keeps no `title`, `detail` or `upgradeUrl`, and `error.errors` keeps only the fields a channel request can carry, each with a fixed sentence in place of the service's message. A `409` on a channel test now says what it most likely means there — delivery for the channel's kind is switched off on the service, so nothing was delivered — instead of the create-oriented advice to read the resource back. Every request of the client `createCronheartApi` returns is now composed inside the one error type a caller catches: an accessor on a request or on its options that throws rejects with `ApiInvalidRequestError` and sends nothing, and a cursor that is not a string is refused the same way. Each request field and each option is read once, a walk reads its options once rather than once per page, and channel ids are copied into a plain array without calling anything on the array handed in. The wire contract moves up a minor version: it states that the write half of the channel kinds is closed, adds a `writers-behind` verdict for a closed write list the service has widened, and states for ports the rule that withholds the service's wording on channel routes and the channel-test meaning of a `409`.
